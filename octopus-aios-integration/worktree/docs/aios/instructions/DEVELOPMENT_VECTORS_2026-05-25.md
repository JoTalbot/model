## Вектор 8: ПАМЯТЬ (САМЫЙ ОСНОВНОЙ) — Приоритет №1
**Определение:** бессмертная память и её унификация.

### Выполнено:
1. **Архитектурное проектирование ПАМЯТИ:** спроектирована и внедрена система контентно-адресуемого хранения на базе хэшей SHA-256 с дедупликацией по содержимому.
2. **MVP Универсального Файлообменника (/admin/memory):**
   - Реализована серверная часть: `POST /api/memory/upload` вычисляет SHA-256 хэш файла, выполняет дедупликацию, сохраняет файл в локальный пул `/var/lib/octopus/memory_pool/` и регистрирует метаданные в PostgreSQL (`memory_records`).
   - Реализована серверная часть: `GET /api/memory/download?ref=...` считывает файл из пула по хэшу и отдаёт его с правильными MIME-типами и заголовком `Content-Disposition` для скачивания.
   - Реализована клиентская часть: добавлена кнопка "Скачать" для файлов схемы `file` в таблице.
   - Создан и внедрен красивый интерактивный клиентский компонент `UploadForm.tsx` (кнопка выбора файла, статус-состояние загрузки с автоматическим обновлением страницы после успешной отправки).
3. **Smoke-тестирование:** Проверено, что все новые API эндпоинты успешно работают через `curl`, а Next.js Admin собирается и развертывается без единой ошибки.

### Следующие шаги:
- [ ] **IPFS интеграция:** Добавить демон IPFS и скрипт синхронизации файлов пула в IPFS сеть для холодного хранения.
- [ ] **Репликация пулов:** Скрипт репликации файлов пула `/var/lib/octopus/memory_pool/` на внешние ноды (например, node3-helsinki) для отказоустойчивости при падении parent ноды.

## Вектор 1: ЖИТЬ (автономность и стабильность) — Приоритет №2
**Определение:** автономность, стабильность работы и непрерывный мониторинг.

### Выполнено:
1. **Стабилизация Smoke-теста:**
   - Исправлена ошибка теста `dynamic control-port registry sync` (ранее ожидал порты `>= 9405`, что было актуально при 6 запущенных детях, но теперь число детей ограничено 4 для предотвращения OOM, поэтому порты ограничены `9401..9404`). Изменено ограничение в `/opt/octopus-smoke.sh` на `>= 9401`.
   - Исправлено предупреждение `guarded local autoscaler capped` (ранее ожидал причину `max_port_reached`, но при высокой нагрузке или малом количестве свободной памяти срабатывает `resource_guard`, что является нормальным поведением). Изменена проверка в `/opt/octopus-smoke.sh` на приемлемость обеих причин.
   - В результате Smoke-тест проходит на **100% успешно (37 pass, 0 warn, 0 fail)**.

### Следующие шаги:
- [ ] OOM killer alert через Prometheus (`container_oom_failures_total`).
- [ ] Автоматическое динамическое снижение CPU limits после завершения ресурсоемкой синхронизации DHT.

**Определение:** снижение сложности кодовой базы, минимизация дублирования и неиспользуемых частей.

### Выполнено:
1. Оптимизирована структура проекта, удалены старые неиспользуемые ассерты из smoke-теста.
2. Проведена интеграция без добавления тяжелых внешних библиотек (использовались нативные Node.js `crypto`, `fs/promises` и веб-стандарт `FormData`).

### Следующие шаги:
- [ ] Провести инвентаризацию сервисов и удалить неиспользуемые (`octopus-child-8304` и `octopus-child-8305`, если они окончательно выведены из эксплуатации).
