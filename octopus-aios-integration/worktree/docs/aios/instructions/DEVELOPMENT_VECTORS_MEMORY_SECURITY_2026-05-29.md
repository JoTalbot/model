# Octopus — Вектор 8: ПАМЯТЬ & БЕЗОПАСНОСТЬ + связанные инициативы
Дата ввода: 2026-05-29
Приоритет: высший для блока ПАМЯТЬ; дополняет `DEVELOPMENT_VECTORS_2026-05-25.md` и общие инструкции №05/№11.

## Главный приоритет
**ПАМЯТЬ & БЕЗОПАСНОСТЬ** — развитие бессмертной, реплицируемой, доступной, защищённой и удобной памяти Octopus.

При проектировании изменений проверять:
1. Увеличивает ли это бессмертие данных?
2. Улучшает ли это безопасность доступа и репликации?
3. Делает ли это память доступнее с разных устройств и при потере связи?
4. Не создаёт ли это платных ресурсов без явного разрешения пользователя?

## 1. Многонодовый IPFS Cluster / Cooperative P2P pinning

### Идея
Сейчас файлы закрепляются (`pin`) только на локальной IPFS-ноде. При выключении сервера доступность CID может снизиться.

### Решение
Создать лёгкий скрипт-координатор, который после загрузки файла на parent-node автоматически рассылает дружественным IPFS-нодам роя команду:

```http
POST /api/v0/pin/add?arg=<CID>
```

Целевые ноды: внешние дружественные узлы Octopus, например `node3-helsinki`, будущие AWS/Oracle/Fly/free-tier ноды, локальные устройства пользователя.

### Требования безопасности
- Не открывать IPFS API публично без защиты.
- Использовать allowlist IP, reverse proxy с token auth или mTLS/VPN-туннель.
- Логировать CID, список нод, результат pin/add, количество успешных реплик.

### Результат
Файл физически закрепляется на нескольких серверах в разных дата-центрах. Это повышает скорость доступа и живучесть памяти.

## 2. Offline-first web-panel / PWA для доступа к Памяти с телефона

### Идея
`/admin/memory` должна быть удобной на телефоне и частично работать без интернета.

### Решение
Превратить Next.js Admin в PWA:
- добавить `manifest.webmanifest`;
- добавить Service Worker для кэширования статических ресурсов;
- реализовать локальное кэширование текстовых заметок и метаданных в IndexedDB;
- добавить мобильный UX для `/admin/memory`;
- предусмотреть режим read-only/offline с синхронизацией после восстановления сети.

### Требования безопасности
- Не хранить долгоживущие пароли в открытом виде в IndexedDB/localStorage.
- Для offline-кэша предусмотреть явное включение пользователем.
- Для чувствительных заметок — шифрование на клиенте или запрет offline-cache.

### Результат
Панель Octopus можно установить как приложение на смартфон, быстро открывать, читать сохранённые заметки/метаданные без сети и синхронизироваться позже.

## 3. OCR и автотегирование скриншотов / документов
Связанный вектор: **УЧИТЬСЯ**, мультимедийный ИИ.

### Идея
Картинки, скриншоты, фото документов и чеки сейчас остаются «слепыми пятнами» для RAG-поиска.

### Решение
Интегрировать фоновый обработчик изображений:
- для `.png`, `.jpg`, `.jpeg`, `.webp`, `.tiff`, PDF-сканов запускать OCR;
- возможные движки: `pytesseract` как базовый лёгкий вариант, `easyocr` как более тяжёлый вариант;
- извлечённый текст сохранять в Postgres-метаданные записи памяти;
- генерировать эмбеддинги для OCR-текста;
- добавлять автотеги: чек, письмо, документ, хостинг, контакты, счёт и т.д.

### Требования безопасности и ресурсов
- OCR запускать фоново, с CPU/RAM лимитами.
- Не ломать загрузку файла, если OCR завершился ошибкой.
- Для приватных документов не отправлять изображения во внешние облачные OCR без явного разрешения пользователя.

### Результат
Можно загрузить скриншот или чек, а позже искать по нему через `/rag`, например: «сколько я потратил на хостинг?» или «найди контакты из письма».

## 4. HTTP-репликация метаданных и файлов без SSH / Cross-node bridge
Связанный вектор: **СОСУЩЕСТВОВАНИЕ И АВТОНОМНОСТЬ**.

### Идея
Репликация на внешние ноды не должна зависеть только от SSH-доступа и приватных ключей.

### Решение
Разработать двусторонний HTTP-мост синхронизации:

На принимающей ноде:
```http
POST /api/v1/memory/replicate
```

Функции:
- endpoint защищён токеном или подписью запроса;
- parent-node отправляет новые файлы и метаданные обычным HTTPS-запросом;
- принимающая нода сохраняет файл в локальный memory-pool;
- обновляет локальную БД или локальный индекс;
- возвращает checksum/sha256 подтверждение.

### Требования безопасности
- Только HTTPS или защищённый туннель.
- HMAC-подпись тела запроса или mTLS.
- Replay protection: timestamp + nonce.
- Ограничение размера запроса и rate limit.
- Проверка SHA-256 после приёма.

### Результат
Репликация работает через NAT/firewall и не требует SSH-ключей. Это повышает переносимость и сосуществование в разных средах.

## 5. Динамическое самолечение памяти / Auto-heal & Garbage Collection
Связанные векторы: **ПАМЯТЬ, ЖИТЬ, УПРОЩЕНИЕ**.

### Идея
Со временем локальный диск может переполниться временными или редко используемыми файлами.

### Решение
Создать интеллектуальный демон-чистильщик:
- отслеживать свободное место на диске;
- при падении free space ниже 10% искать кандидатов на холодное хранение или удаление локальной копии;
- кандидаты: временные файлы, файлы без флагов `WORM`/`Important`, файлы без обращений более 30 дней;
- перед удалением локальной копии проверять:
  - есть ли файл в IPFS;
  - закреплён ли CID на достаточном количестве дружественных нод;
  - совпадает ли SHA-256;
- при запросе удалённой локальной копии — восстанавливать из IPFS/реплики.

### Требования безопасности
- Никогда не удалять файлы с флагами `WORM`, `Important`, `Legal`, `ArchiveOnly`, если нет отдельного правила.
- Все удаления делать через двухфазный процесс: `candidate -> cold_verified -> local_pruned`.
- Вести журнал GC-решений.
- Первую версию запускать в dry-run режиме.

### Результат
Octopus управляет горячим и холодным слоями памяти, освобождает диск без потери данных и повышает автономность.

## Рекомендуемый порядок реализации
1. **HTTP-репликация без SSH** — базовый безопасный транспорт между нодами.
2. **Многонодовый IPFS pin coordinator** — закрепление CID на дружественных нодах.
3. **Auto-heal & GC в dry-run** — контроль диска без риска потери данных.
4. **OCR pipeline** — делает изображения частью RAG-памяти.
5. **PWA offline-first** — улучшает доступность памяти для пользователя.

## Метрики успеха
- `replication_count >= 3` для важных файлов.
- `pin_success_rate >= 95%` по дружественным IPFS-нодам.
- `memory_restore_test` проходит из IPFS/реплики без parent-node.
- OCR-текст доступен в RAG-поиске для новых изображений.
- PWA устанавливается на телефон и открывает offline-кэш метаданных.
- GC сначала работает в dry-run без ложных кандидатов на удаление важных файлов.
