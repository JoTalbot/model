## 1. Цели роадмапа (что значит "бессмертная")
B1. **Минимум 3 независимые копии** во всех состояниях (уже есть; нужно усилить непрерывную верификацию).
B2. **Восстановление за минуты** из любой одной копии без участия других (drill автоматический).
B3. **Криптоверификация целостности** на уровне манифеста (sha256 от sha256-ов) — обнаружение тихой порчи.
B4. **Снижение количества операций репликации в 100-1000×** (packstore) — экономия денег и латентности.
B5. **Унификация интерфейса**: один CAS-API (read/write/list/verify), работающий поверх loose/pack/s3/ec2.
B6. **Доступ с любого устройства** (web/CLI/mobile-friendly) к чтению объектов памяти через единый endpoint.
B7. **Оффлайн-копия**: периодический самодостаточный архив (1 файл tar.zst + манифест), который можно скачать руками.

## 2. Независимые ПОТОКИ (могут идти параллельно, разными change-window'ами)

- A0. Замеры на копии (сделано: 14МБ -> 8.54МБ zstd-19, распаковка 0.056с).
- A1. Прототип packer + pack_index в Postgres, DRY-RUN (loose не удаляем). Замер скорости/коэффициента.
- A2. Reader с фоллбэком cache -> loose -> pack. Включить как ДОПОЛНИТЕЛЬНЫЙ путь. smoke 40/0/0.
- A3. Pack-aware репликатор: двойная запись (loose-poштучно + pack-пакетами) на S3/EC2. Сверка.
- A4. Переключить аудитор/restore-drill на pack-манифест. Подтвердить инвариант 3 копий на pack-уровне.
- A5. GC loose-объектов, которые в pack И в 3 копиях. Никогда не удалять без подтверждения копий.
- A6. Архивировать старый file-per-object путь как fallback ≥1 неделя.
Зависимости: НЕТ от других потоков (можно начать сразу).
Откат на каждом шаге: выключить новый путь, loose остаётся источником правды.

- I4. После каждого шага: smoke-тест + audit + restore-drill — все должны быть зелёные. Иначе откат.
- I5. Никакого автономного создания серверов/IAM-ключей. Все WAVE-команды — по явному «да» пользователя.

## 6. Метрики успеха роадмапа
- Кол-во операций репликации (PUT/HTTP) на полную пересинхронизацию: 20k -> <100.
- Время репликации: текущие минуты/таймауты -> <10c.
- Время восстановления из любой копии: <2 мин для всего pool.
- Покрытие 3 копиями: 1.0 непрерывно (алерт <5 мин при просадке).
- Локальное место под память: 90МБ -> ~10МБ (при тех же 20k объектов).
- Время аудита целостности (manifest sha): <1с.
