# OCTOPUS GET-ONLY COMMAND PROTOCOL v2.4

## Цель
Обеспечить стабильное и безопасное управление системой Octopus через простые GET-запросы, обходя ограничения защищенных чат-сред.

## Принципы
1. **Безопасность**: Вместо передачи произвольных команд через URL, используется строгий allowlist разрешенных действий.
2. **Простота**: Все сложные bash-скрипты инкапсулированы на сервере.
3. **Логирование**: Каждое действие автоматически записывается в `~/agents/-Octopus/logs/`.
4. **Защита**: Деструктивные операции требуют подтверждения (`&confirm=YES`).

## Эндпоинты

### 1. Список всех действий
Вернет JSON со всеми доступными командами и их описанием.
`http://api.autosklo.org.ua/actions?token=<TOKEN>`

### 2. Выполнение действий
Формат: `http://api.autosklo.org.ua/run/{action}?token=<TOKEN>`

**Категория: core**
- `health`: Быстрая проверка связи.
- `status`: Статус Октопуса (SLO, Memory, Disk).
- `info`: Системные ресурсы и количество нод.
- `version`: Версия протокола (v2.4).

**Категория: audit**
- `audit-full`: Полный аудит системы.
- `audit-disk`: Детализация занятого места.
- `audit-node-modules`: Поиск тяжелых зависимостей.
- `audit-fleet`: Сверка всех нод флота (Swarm).
- `audit-media`: Поиск медиафайлов вне IPFS.
- `audit-ipfs`: Статус хранилища объектов.
- `processes`: Топ процессов по RAM.

**Категория: clean (Требуют &confirm=YES)**
- `aggressive-clean`: Глубокая очистка (Docker, npm, logs).
- `docker-prune`: Очистка неиспользуемых контейнеров/образов.
- `tmp-clean`: Очистка временных папок.
- `offload-media`: Автоматический перенос медиа в IPFS.

### 3. Авторизация
Токен передается параметром `?token=...`.
Мастер-токен хранится в `/root/agents/.octopus_autopilot_token`.

## Синхронизация
Данный протокол реализован в `/root/agents/-Octopus/autopilot/octopus_get_actions_router.py` и интегрирован в основной API.
