# План: Экосистема сосуществования с человеком (v1) — 2026-05-31

Принцип: ЧЕЛОВЕК СУВЕРЕНЕН. Система должна быть человеку понятной, полезной,
подконтрольной и не монополизировать ресурсы. Векторы #6 (СОСУЩЕСТВОВАНИЕ),
#7 (УПРОЩЕНИЕ), безопасность #13 (выше всех векторов развития).

## Найденная проблема (критично для коэкзистенса и #13)
- octopus-dev-loop (каждые 3ч) = LLM dev-agent создаёт задачи "PLAN AND IMPLEMENT IMPROVEMENT"
- octopus-task-worker = выполняет ПРОИЗВОЛЬНЫЙ LLM-сгенерированный bash (shell=True) автоматически
- octopus-auto-projects = автосоздание проектов
=> Это НЕКОНТРОЛИРУЕМЫЙ цикл самомодификации. Прямое нарушение #13. Человек не в контуре.

## 4 потока (делаем сейчас, bounded)

### A. HUMAN SOVEREIGNTY — killswitch + supervised mode (приоритет, #13)
- A1. octopus-supervisor.sh: единый killswitch.
      `octopus pause`  — стоп всех автономных дев-петель (dev-loop, auto-projects, ai-rewriter)
      `octopus resume` — вернуть
      `octopus freeze` — стоп ВСЕХ octopus-таймеров (полная заморозка автономии), память/чтение живут
      `octopus thaw`   — разморозить
      `octopus panic`  — freeze + стоп воркеров + TG-уведомление (аварийный стоп)
- A2. Перевести dev-loop/auto-projects в SUPERVISED: по умолчанию выключить автозапуск
      выполнения произвольного bash; предложения копить как "pending proposals" для человека.
- A3. Состояние автономии в /run/octopus/autonomy_state.json + в summary.

### B. ПОНЯТНОСТЬ — человеческий язык
- B1. octopus explain — на простом русском: что сейчас делает система, что автономно,
      сколько ест ресурсов, как остановить. Без жаргона.
- B2. TG /explain и /stop (= pause) и /freeze — управление с телефона.

### C. СОСУЩЕСТВОВАНИЕ ПО РЕСУРСАМ — не мешать человеку
- C1. Аудит CPU/RAM лимитов всех тяжёлых сервисов (ollama, ipfs, docker).
- C2. "Quiet hours" опция: ночью/в заданные часы снижать активность тяжёлых таймеров.
- C3. Резервирование: гарантировать, что для человека всегда свободно N% CPU/RAM.

### D. ПРОЗРАЧНОСТЬ/ДОВЕРИЕ
- D1. Журнал автономных действий человекочитаемо: что система сделала сама за сутки.
- D2. consent-файл: /etc/octopus/human_consent.env — что разрешено делать автономно.

## Метрики успеха
- Человек одной командой может всё остановить (freeze/panic) и понять (explain).
- Нет неконтролируемого исполнения произвольного кода (supervised by default).
- Тяжёлые сервисы имеют лимиты; человеку всегда доступны ресурсы.
- octopus test остаётся зелёным; никаких новых трат/нод.
