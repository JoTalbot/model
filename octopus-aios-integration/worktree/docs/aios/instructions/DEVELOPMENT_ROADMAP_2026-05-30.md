# Octopus — Roadmap по всем векторам развития
Обновлено: 2026-05-30 03:58 UTC

Приоритет: **ПАМЯТЬ > ЖИТЬ > УПРОЩЕНИЕ > СОСУЩЕСТВОВАНИЕ > остальные**.

## Уже запущено в этой итерации
- Исправлен restore drill: выбор идет по актуальным `sha256:*` ref, а не по legacy `ref:pingvin:*`.
- Убрана ложная критика `OctopusMemoryRestoreDrillFailed/Mismatch`; алерты = 0.
- Стабилизирован Garage: устранен restart-loop из-за несовместимого `replication_factor` между main и AWS.
- Санитизирован `replication.env` на main и AWS.

---

## 1. ПАМЯТЬ
### Цель
Сделать память канонической, восстанавливаемой и независимой от одной ноды.
### План
1. Канонизировать restore drill только на `sha256:*` объектах.
2. Ввести политику `ref -> sha256 canonical`, убрать зависимость от legacy-источников.
3. Добавить отчет по репликации: local pool / IPFS / Garage S3 / AWS HTTP.
4. Подготовить авто-проверку: есть ли минимум 2 независимые копии для важных файлов.
### Уже начато
Пункт 1 выполнен. Массовая канонизация завершена (20к+ записей).

## 2. ЖИТЬ
### Цель
Минимизировать ложные алерты, restart-loops и деградации.
### План
1. Добавить отдельную проверку Garage peering/config drift.
2. Завести SLO: smoke=green, alerts=0, restore drill=ok.
3. Автоматически фиксировать рост `NRestarts` > 20 в логе обслуживания.
### Уже начато
Исправлен реальный restart-loop Garage.

## 3. УПРОЩЕНИЕ
### Цель
Убирать хрупкость и дубли.
### План
1. Унифицировать env-файлы (`replication.env`, `next-admin.env`) и валидацию формата.
2. Убрать legacy-зависимости от Pingvin в критических проверках.
3. Свести конфигурацию памяти к одному каноническому пути: `sha256 -> pool -> IPFS/S3/AWS`.
### Уже начато
Исправлен битый `replication.env` и legacy-выборка restore drill.

## 4. СОСУЩЕСТВОВАНИЕ
### Цель
Octopus должен жить рядом с другими сервисами без конфликтов и лишней экспозиции.
### План
1. Проверить AWS-ноду на лишние открытые порты (Garage S3/Admin/metrics).
2. Ограничить внешнюю поверхность только тем, что реально нужно.
3. Добавить документированную матрицу портов: public / localhost / tunnel-only.

## 5. РАЗМНОЖАТЬСЯ
### Цель
Расширять рой только безопасно и бесплатно.
### План
1. Довести AWS free-tier ноду до роли полноценной memory-replica без рискованного peering.
2. Подготовить шаблон бесплатной secondary-ноды (IPFS + HTTP receiver + exporter).
3. Новые платные VPS не создавать без явной команды пользователя.
### Уже начато
AWS free-tier нода остается в строю как receiver/IPFS/exporter.

## 6. РАЗВИВАТЬСЯ
### Цель
Улучшать UX и полезность памяти.
### План
1. Добавить в UI статус копий файла: local / IPFS / AWS / S3.
2. Показать причину деградации restore drill прямо в `/admin/memory/health`.
3. Подготовить отдельную карточку "Storage topology" в admin.
### Уже начато
В `/admin/memory` уже добавлены бейджи копий `LOCAL`, `AWS`, `IPFS`, `PIN AWS`, `S3`; добавлена storage topology card, а в `/admin/memory/health` выведены причины деградации restore drill и Garage preflight.

## 7. УЧИТЬСЯ
### Цель
Наращивать память о собственных ошибках.
### План
1. Каждую инфраструктурную аварию сохранять как отдельный experience-файл.
2. Собирать типовые классы сбоев: env corruption, legacy refs, peering mismatch, orphan process.
3. Индексировать lessons learned в `experience_index` для быстрых подсказок агенту.
### Уже начато
Создается новый experience-файл по ложному restore drill и Garage mismatch.

## 8. МЕНЯТЬСЯ
### Цель
Гибко менять топологию без поломок.
### План
1. Разделить режимы Garage: `standalone` и `clustered`, без полу-состояний.
2. Перевести критичные проверки на capability-based подход: что реально умеет нода.
3. Добавить preflight-check перед включением multi-node storage.
### Уже начато
Создан и прогнан `garage preflight`: transport/config OK, но настоящий replicated cluster пока запрещён (`replication_factor=1`, `NO ROLE ASSIGNED`, `bad_peers=true`). Подготовлен отдельный `Garage migration plan`.

## Следующий исполняемый пакет
1. Документировать портовую матрицу main/AWS.
2. Вынести проверку формата env в отдельный script/timer dry-run.
3. Подготовить безопасный план включения настоящего multi-node Garage только после отдельного preflight.
